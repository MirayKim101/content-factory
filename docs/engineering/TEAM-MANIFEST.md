# Content Factory — постоянный манифест AI-команды

Статус: действующий
Дата: 2026-09-01

## Что означает «постоянная команда»

Постоянными являются роли, инструкции, порядок работы и память проекта. Живые
процессы субагентов создаются для конкретной задачи и могут завершиться при
закрытии Codex. После нового запуска orchestrator восстанавливает команду из
этого манифеста и `CURRENT-HANDOFF.md`, а не полагается на память старого
процесса.

| ---------------------- | ------------------------------------- | --------------------------------- | ---------------------------------------------------------- |
| Manager / Orchestrator | основной чат                          | `Manager — <slice>`               | постановка задачи, владельцы, синтез и связь с владельцем  |
| Solution Architect     | `.codex/agents/architect.toml`        | `Solution Architect — <decision>` | границы, контракты, ADR и существенные решения             |

| Backend Engineer       | `.codex/agents/backend.toml`          | `Backend Engineer — <slice>`      | NestJS, PostgreSQL, BullMQ, workers, FFmpeg и integrations |
| Frontend Engineer      | `.codex/agents/frontend.toml`         | `Frontend Engineer — <slice>`     | Nuxt, FSD, формы, статусы и browser UX                     |

## Правила созыва

Не запускать всю команду без необходимости.

1. Orchestrator всегда активен.
2. Architect и Business Analyst созываются вместе, когда решение одновременно
   меняет техническую архитектуру и экономику масштаба.
3. Один implementer владеет одним вертикальным срезом.
4. Frontend и backend работают параллельно только после утверждения контракта и
   при непересекающихся файлах.
5. QA добавляется для сложных failure/race/job сценариев.
6. Independent Reviewer обязателен перед приёмкой и не исправляет свою находку.
7. DevOps создаётся только для инфраструктурной области.

## Восстановление после запуска Codex

Orchestrator обязан:

1. прочитать `AGENTS.md`;
2. прочитать этот манифест и `CURRENT-HANDOFF.md`;
3. проверить `git status --short --branch` и последний коммит;
4. проверить, какие dev-процессы и контейнеры действительно работают;
5. не считать старых субагентов доступными после перезапуска;
6. создать только профессии, необходимые следующему незавершённому шагу;
7. передать им acceptance criteria, ownership файлов и запрет отменять чужие
   изменения.

## Протокол «сохрани состояние»

По просьбе владельца завершить или сохранить работу orchestrator:

1. перестаёт начинать новые срезы;
2. дожидается активных агентов либо безопасно останавливает их;
3. получает от каждого фактический статус и незакрытые пункты;
4. запускает релевантные проверки;
5. обновляет `CURRENT-HANDOFF.md`, документацию и Notion;
6. удаляет только созданные командой временные процессы/артефакты;
7. проверяет секреты и состав staging;
8. создаёт commit и push, если срез действительно готов;
9. сообщает владельцу commit, проверки, работающие сервисы и первый следующий
   шаг.

Незавершённая работа не помечается готовой только ради сохранения. В handoff
явно записываются blocker, dirty files и команда воспроизведения.
